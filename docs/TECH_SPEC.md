2. ПРОБЛЕМА И РЕШЕНИЕ
================================================================================
Проблема целевой аудитории (МСБ):
- У МСБ нет штатного CISO / специалиста по ИБ.
- Регуляторика сложная: 152-ФЗ, Приказ ФСТЭК № 21, КоАП ст. 13.11 (штрафы до 700 000 ₽).
- Консультанты берут 300 000+ ₽ за "бумажную безопасность" и 150 000+ ₽ за Модель угроз ИСПДн.
- Документы пылятся, через год приходят проверки с штрафами.
- Сисадмины МСБ не умеют писать Модели угроз и Проекты защиты ИСПДн по ФСТЭК.

Решение:
Простой SaaS, который за 5 минут:
1. Генерирует пакет юридически корректных документов.
2. Превращает комплаенс из разового действия в непрерывный процесс.
3. Автоматически напоминает о дедлайнах и изменениях в законах.
4. Обрабатывает сложные сценарии (отзывы согласий, проверки РКН).
5. Разделяет процессы для разных типов субъектов ПДн.
6. Автоматически формирует Модель угроз и Проект защиты ИСПДн по методике ФСТЭК.

================================================================================
Основной сегмент: Малый и средний бизнес в РФ (15-500 сотрудников).
Типичные клиенты: Интернет-магазины, онлайн-сервисы, HR-агентства, медицинские клиники, образовательные учреждения, финтех-стартапы.
Лица, принимающие решения (ЛПР): Собственник / CEO, Финансовый директор, HR-директор, Системный администратор, Технический директор / CTO (для модулей ИСПДн).

Типы субъектов ПДн у клиентов:
- Сотрудники (хранение 75 лет).
- Клиенты (хранение 3 года после последнего заказа).
- Кандидаты (хранение 6 месяцев после отказа).
- Контрагенты (хранение 5 лет).

5. ПРОДУКТОВАЯ СТРАТЕГИЯ
================================================================================
Модель "Land and Expand":
1. Зацепить болью (152-ФЗ).
2. Доказать ценность через бесплатный пакет.
3. Продать подписку через модуль обработки отзывов согласий.
4. Расширить чек через модули ИСПДн (Модель угроз + Проект защиты).
5. Выйти на Enterprise через ИСПДн 1-2 класса и on-premise.

7. ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ
================================================================================
7.1 Бесплатный пакет (Hook):
5 документов с авто-подстановкой реквизитов: Приказ, Политика, Согласие, Уведомление РКН, Журнал обращений.
Опросник из 6 вопросов для генерации.

7.2 Разделение субъектов ПДн:
Реестр с типизацией (employee, client, candidate, contractor). Разные шаблоны согласий, сроки хранения и процедуры отзывов для каждого типа.

7.3 Модуль "Обработка отзывов согласий" (Retention):
Воркфлоу из 7 этапов: Регистрация → Идентификация данных → Чек-лист → Генерация задач → Контроль выполнения → Формирование документов (Акт уничтожения, Уведомление) → Архивирование.

7.4 Модуль "Защита ИСПДн" (Масштабирование, тарифы Pro/Business/Enterprise):
- Реестр ИСПДн: Карточка системы (класс защищенности 1-4, тип развертывания, наличие интернета, ОС, существующие средства защиты).
- Конструктор Модели угроз (ФСТЭК 2021): Визард, который на основе параметров ИСПДн автоматически подбирает релевантные угрозы из БДУ ФСТЭК (например, если есть интернет + Windows → добавляет БДУ:ФСТЭК.ВР.04). Генерирует PDF "Модель угроз безопасности ПДн".
- Генератор Проекта защиты (Приказ ФСТЭК № 21): Сопоставляет выявленные угрозы с мерами из Приложения к Приказу № 21. Сравнивает с уже внедренными средствами и формирует план мероприятий по устранению разрывов. Генерирует PDF "Проект защиты ИСПДн".
- Справочники ФСТЭК: Встроенные, обновляемые администратором платформы справочники БДУ и мер защиты.
- Дисклеймеры: "Документ сформирован автоматически... Для ИСПДн 1 и 2 класса требуется экспертиза сертифицированным специалистом. Для 3 и 4 класса оператор принимает решение самостоятельно".

8. ТЕХНИЧЕСКАЯ АРХИТЕКТУРА
================================================================================
- Backend: Python + FastAPI
- Frontend: Next.js (React) + TypeScript
- База данных: PostgreSQL
- Генерация PDF: WeasyPrint (backend) / jsPDF (frontend)
- Аутентификация: JWT + bcrypt + TOTP (RFC 6238)
- Деплой: Docker + Docker Compose
- Хостинг (демо): Vercel
- Хостинг (продакшен): Selectel / Yandex Cloud

Схема БД (ключевые новые таблицы для ИСПДн):
- ispdn_systems (карточки систем)
- fstec_threats (справочник угроз БДУ)
- fstec_measures (справочник мер Приказа № 21)
- system_threats (связь Система ↔ Угроза)
- system_measures (связь Система ↔ Мера защиты)
- threat_models (сгенерированные модели)
- protection_projects (сгенерированные проекты защиты)

9. БЕЗОПАСНОСТЬ И СООТВЕТСТВИЕ 152-ФЗ
================================================================================
- Серверы в РФ (Selectel / Yandex Cloud).
- Шифрование at-rest (PostgreSQL TDE или LUKS) и in-transit (TLS 1.3).
- Хэширование паролей (bcrypt).
- Двухфакторная аутентификация: Открытый стандарт TOTP (RFC 6238). Поддержка любых приложений (рекомендуем российские: Bitrix OTP, Яндекс.Key, Сбербанк OTP; поддерживаются международные: Google/Microsoft Authenticator, Authy). Резервные методы: SMS, Email, Backup-коды.
- Логирование действий (таблица audit_logs).
- Разделение ролей (админ сервиса ≠ админ клиента).

10. РЕГУЛЯТОРНЫЕ ТРЕБОВАНИЯ ДЛЯ SaaS-ПРОВАЙДЕРА
================================================================================
- Статус: Система управления процессами (GRC), НЕ средство защиты информации (СЗИ).
- Лицензия ФСТЭК: НЕ нужна для старта (мы не разрабатываем СЗИ, не шифруем трафик).
- Обязательные требования для запуска: Уведомление в Роскомнадзор (мы оператор ПДн своих клиентов), серверы в РФ, шифрование, логирование, публичная политика конфиденциальности, оферта с отказом от ответственности за содержание документов клиентов.
